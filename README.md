# G検定 用語クイズ

`G検定_用語集.xlsx` を元データにした、G検定対策の学習用クイズサイトです。
バックエンドを持たない静的サイトなので、GitHub Pages や Vercel にそのまま置けます。

- クイズは5種類：用語当て（解説→用語）／逆引き（用語→解説）／組み合わせ（マッチング）／正誤判定（○×）／比較問題
- トップ画面で、出題数（10／20／50）、分野（複数選択）、シラバス区分を選べます
- 間違えた問題は「苦手」としてブラウザの localStorage に記録され、「苦手な問題だけ復習」で出題できます。正解すると記録から外れます
- 回答画面の右下に、問題IDや用語集No（比較は比較ID／観点）を表示します。問題の誤りを報告するときに使ってください

技術構成：Vite + React + TypeScript、テストは Vitest、Excelの変換は SheetJS（Node）です。

## ローカルで起動する

Node.js 20 以上が必要です（動作確認は v24 で行いました）。

```bash
npm install
npm run dev        # http://localhost:5173 で開く（同じネットワークのスマホで見るなら: npm run dev -- --host）
```

本番と同じ形で確認したいとき：

```bash
npm run build      # 型チェックをしてから dist/ に出力
npm run preview    # http://localhost:4173
```

公開先：https://mrarther.github.io/gkentei-quiz/

## 問題データを直すとき（Excelを更新したとき）

**元データは `G検定_用語集.xlsx` だけです。** `src/data/*.json` はExcelから自動で作るファイルなので、Git には入れていません。
`npm run dev`、`npm run build`、`npm test`、`npm run audit` を実行すると、毎回先にExcelをJSONに変換します。
GitHub に push すると、Actions が「変換 → テスト → audit → ビルド → 公開」を行います。

### パソコンで直す場合

1. `G検定_用語集.xlsx` を Excel で編集して保存する（ファイル名とシート名、列の見出しは変えない）
2. 手元で確認する

   ```bash
   npm run audit      # エラーと警告の一覧。エラーが0件なら公開できる
   npm run dev        # 画面で確認
   ```

3. コミットして push する。数分後にサイトが更新されます

   ```bash
   git add G検定_用語集.xlsx
   git commit -m "問題データを修正"
   git push
   ```

### ブラウザだけで直す場合

1. GitHub のリポジトリのページで「Add file → Upload files」から、修正した `G検定_用語集.xlsx` をアップロードする（同じ名前のファイルが上書きされます）
2. 「Commit changes」を押す
3. 「Actions」タブで処理の結果を確認する。緑のチェックが付けば公開済みです。赤い×が付いたときは、ログの「Run npm run audit」か「Run npm test」を開くと、どのシートの何行目が原因かがわかります。データにエラーがある間は公開されず、前の版がそのまま表示されます

### 問題を解きながら直す（編集モード）

1. サイトを **`?edit=1` を付けて** 開く（例：https://mrarther.github.io/gkentei-quiz/?edit=1 ）。一度開けば、そのブラウザでは編集モードのままになります。終えるときはトップの「編集モードを終える」を押します
2. 回答画面の「✎ 問題を修正」を押すと、その問題の元データを直せます
   - 用語当て・逆引き：用語集の「用語」「意味（解説）」「G検定の押さえどころ」。選択肢に使った他の用語も直せます
   - 正誤判定：穴埋め問題の「穴あき解説文」と、各空欄の正解・誤答の選択肢
   - マッチング：5語それぞれの用語集の項目と、語句の元になった穴埋め問題
   - 比較問題：「違いの要点」と、その観点の各用語の「特徴」
3. 「保存して問題を作り直す」を押すと、すぐに問題が作り直されて表示に反映されます。修正はそのブラウザにだけ保存され、他の人には見えません
   - 空欄の【1】【2】…を消したり、選択肢が重複したりすると、保存前にエラーを表示します
4. 直し終わったら、トップの「修正の一覧」→「ファイルに保存」で `edits-日付.json` を書き出します（スマホなら AirDrop などでパソコンへ送る）
5. パソコンで Excel に書き戻して公開する

   ```bash
   pip3 install openpyxl                               # 初回だけ
   npm run apply-edits -- ~/Downloads/edits-20261103-1530.json
   git add G検定_用語集.xlsx && git commit -m "問題データを修正" && git push
   ```

   `apply-edits` は修正したセルだけを書き換えます。行の色・数式・フィルタ・セルの書式はそのまま残ります。書き込んだあとは、続けて自動でチェック（audit）を実行します。
   - 直す前の値が今の Excel と違うセル（Excel を直接編集した、など）は、上書きせずに一覧で知らせます。上書きしてよければ `--force` を付けます
   - 書き込まずに内容だけ確かめたいときは `--dry-run` を付けます
   - 書き込む前に Excel を閉じておいてください
6. 公開サイトが更新されると、「修正の一覧」でその修正に「Excelに反映済み」と表示されます。「反映済みの○件を一覧から消す」で片付けます

### 誤りの報告を受けたとき

回答画面の右下に、問題の識別子が表示されています。これを手がかりにExcelの該当行を探せます。

| 表示 | Excel の場所 |
|---|---|
| `用語集No.21` | 「用語集」シートの No 列 |
| `Q199（用語集No.199）` | 「穴埋め問題」シートの 問題ID 列 |
| `C020／潜在変数（用語集No.2）` | 「比較問題データ」シートの 比較ID 列と観点 列 |

マッチングの語句の横に出る `Q108` なども、穴埋め問題の問題IDです。

別の場所にあるファイルを変換したいときは、`npm run convert -- path/to/book.xlsx` のようにパスを渡します。

### 変換スクリプトがチェックすること（`scripts/convert.ts`）

列は見出しの名前で探すので、列の順番を入れ替えても動きます。次のどれかが見つかると、シート名と行番号を表示して止まります。

- 必須の列が無い／必須のセルが空
- 用語集のNoが重複している、シラバス区分が「記載あり／関連用語／最新動向（シラバス外）」のどれでもない
- 穴埋め：用語集Noが用語集に無い、正解番号が1でない、正解が選択肢1と違う、選択肢が重複している、本文の【n】と空欄番号が一致しない
- 比較：比較IDが比較テーマに無い、ある観点で一部の用語の特徴が欠けている、同じ観点に同じ特徴がある

使うシートは「用語集」「穴埋め問題」「比較テーマ」「比較問題データ」の4つです。「モデル年表」「分野別件数」「出典と注記」は読みません。

### audit の見方（`npm run audit`）

- **エラー**（終了コード1）：選択肢の重複、正解が選択肢に無い、用語名が伏せられていない、マッチングの正解が1通りに決まらない、など
- **警告**（人の目で確認するもの）
  - 伏せきれなかった可能性のある語：用語名に含まれる英単語が、伏せた後の解説に残っているもの。「Faster R-CNN」の解説に出てくる「R-CNN」のように、別の用語を指していることが多いです。答えがわかってしまう場合は、解説文を直してください
  - 他の分野から誤答を補った分野：その分野の語が4語未満のもの
  - マッチングに出せない用語：穴埋めの正解に、使える語句（下記の条件）が1つも無い用語
  - 比較で用語名を伏せた特徴文

## クイズの作り方（`src/lib/generators/`）

選択肢の並びは毎回シャッフルします。Excelでは正解が常に選択肢1ですが、画面にそのままの順で出ることはありません。

| クイズ | 作り方 |
|---|---|
| 用語当て | 解説の中の用語名を「〇〇」に伏せて出す。誤答は同じ分野の別の用語から3つ選び、足りなければ他の分野から補う |
| 逆引き | 用語を出し、4つの解説から選ばせる。誤答の解説も、それぞれの用語名を伏せる |
| マッチング | 用語5つと語句5つを組にする。語句には穴埋めの正解を使う。4文字以上で、数字＋単位や社名だけのもの、用語名を含むものは使わない。各語句が、出題した5語のうち自分の用語の解説にしか出てこないことを確かめて、正解が1通りに決まる組だけを出す |
| 正誤 | 穴埋めの1問を使い、約半分は全部の空欄を正解で埋めた正しい文、残りは空欄を1つだけ誤答で埋めた誤りの文にする。回答後に入れ替えた箇所を示す |
| 比較 | 「特徴→用語」と「用語＋観点→特徴」をおよそ半々で出す。選択肢の数はテーマの用語数（2〜4）。回答後に「違いの要点」を表示する |

用語名を伏せるルール（`src/lib/mask.ts`）：用語名を括弧の外側の「／」「 / 」で分けた各部分、括弧の前の部分、括弧の中の正式名を伏せます。さらに、括弧の中を「：」「・」「、」で分けた各部分（例：`MSE・RMSE・MAE`）と、「・」で並べた名前（例：`AIC・BIC`）も伏せます。照合では、全角と半角、英字の大文字と小文字を区別しません。

## デプロイ

`vite.config.ts` で `base: './'` にしているので、サブパス（`https://<user>.github.io/<repo>/`）でもそのまま動きます。

### GitHub Pages

設定は済んでいます（リポジトリ `mrarther/gkentei-quiz`、Settings → Pages → Source は「GitHub Actions」）。
`main` に push すると `.github/workflows/deploy.yml` が動き、テスト、audit、ビルドのあとに公開されます。手動で再実行したいときは、Actions タブの「Deploy to GitHub Pages」で「Run workflow」を押します。

### Vercel

1. Vercel で「Add New → Project」から、このリポジトリを読み込む
2. Framework Preset は **Vite**、Build Command は `npm run build`、Output Directory は `dist`（どれも自動で設定されます）
3. Deploy。以後は push するたびに自動で更新されます

### 手動で置く場合

`npm run build` で作った `dist/` の中身を、静的ファイルとして任意のサーバーに置けば動きます。

## ディレクトリ構成

```
scripts/convert.ts        Excel → JSON
scripts/audit.ts          全データの生成チェック
scripts/apply_edits.py    編集モードの修正を Excel に書き戻す
src/data/*.json           Excelから自動生成（Git管理外）
src/lib/mask.ts           用語名の伏せ字
src/lib/generators/       各クイズの問題生成（純粋関数。乱数は引数で受け取る）
src/lib/storage.ts        localStorage（苦手リスト・履歴・前回の設定）
src/components/           画面
tests/                    Vitest のユニットテスト
```
